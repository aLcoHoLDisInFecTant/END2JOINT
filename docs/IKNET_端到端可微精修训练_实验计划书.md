# IKNET 端到端可微精修训练 — 实验计划书

> 验证"端到端 unroll 可微精修"训练出的种子,能否在**更少迭代步数**下达到部署精度,从而把工作量从迭代器搬到网络上(对应甲方诉求:更多用模型、少用迭代、精度不退)。

**适用对象**:`examples/ACTIBOT/end2joint/` 的 IKNET(`ResidualMLP`)+ `fk_correction` 转换链
**前置参考**:`IKNET_TEST_REPORT_zh.md`(L1/L2 测试口径)、`IKNET_开发策划案.md`(§1.4 精修、§3.3 训练)

---

## 0. 目的与背景

**核心问题**:当前 `fk_correction` 是**训练完成后才拼接**的事后处理,网络在训练时从未收到"下游有精修器"的梯度信号,因此没有动机产出"两步就能修好"的种子;它能用,是靠部署时 15 步 / 逐帧的 DLS 迭代硬修出来的。

**本实验验证的假设**:把可微精修器 unroll 进训练、对精修后输出回传梯度(refiner-aware 训练),能让网络学到"落在精修器两步可收敛区域"的种子,从而在小迭代步数 `K` 下即达部署精度。

**为什么这是"用模型更多"的最高杠杆改动**:它不牺牲精度地板(精度仍由数值精修兜底),而是把达标所需的 `K` 压低——等价于在固定精度下把活从迭代搬到模型。

**明确的范围边界**

- 只评估 **E2(endpose → joint 转换链)**,不涉及 VLA(E1)。输入用 in-distribution 的真值 endpose(`FK(录制 action)`),与测试报告 L2 一致。
- 本实验**不掺合成 FK 数据**、**不改输入表示(rpy / 6D)、不加 Δx 输入**——这些是各自独立的消融,混进来会污染结论。本实验唯一的自变量是"损失定义在哪里 + 有无 unroll"。

## 1. 假设与判定标准(预先登记,不事后凑)


| 编号  | 假设                                                              |
| --- | --------------------------------------------------------------- |
| H1  | 把损失从关节 MSE 换成任务空间 FK 损失(C0→C1),会降低达标所需 `K`(任务损失不惩罚等价合法解,种子更"对") |
| H2  | 在 C1 基础上 unroll 可微精修(C1→C2),会进一步降低达标所需 `K`(种子被精修器收敛行为反向塑形)      |


**部署精度目标(**`K`* **的达标线,需确认)**:末端位置 mean < 1.0 mm 且 max < 2.0 mm,姿态 < 0.5°。 (参照报告 L2:K=15 时可达 0.02mm/~0°,目标是用更小 K 达到可用精度,而非超越地板。)

**决策规则(预先写死)**

- **采纳 unroll**:C2 在 `K ≤ 3` 达标,而 C0 需 `K ≥ 8`;且 C2 在 `K`* 下自回归不漂移、自碰撞率不升、精度地板(K=15)不退。
- **只采纳任务损失、不上 unroll**:C1 已把 `K`* 拉到很小,C2 相对 C1 的 `K*` 改善不足阈值。
- **改善值阈值**:等精度下 `K`* 至少减少 **≥ 50%** 才认为 unroll 值得其工程复杂度。

## 2. 实验设计:三条件隔离

直接对比 C0 与 C2 会把"换损失"和"加 unroll"两个改动捆在一起、分不清功劳,因此必须设三条件:


| 条件                 | 训练损失               | 训练时精修器            | 推理时精修                | 隔离的变量                |
| ------------------ | ------------------ | ----------------- | -------------------- | -------------------- |
| **C0(当前基线)**       | 关节 MSE(对录制 action) | 无                 | 生产 fk_correction(事后) | 参照                   |
| **C1(任务空间种子)**     | FK 任务损失(算在裸种子上)    | 无                 | 生产 fk_correction(事后) | C0→C1 = 换损失(改动 A)    |
| **C2(端到端 unroll)** | FK 任务损失(算在精修后输出上)  | K_train=1~2 步可微精修 | 生产 fk_correction(事后) | C1→C2 = unroll(改动 B) |


**C2 子变体(顺手测)**:C2a = 同时加一项对裸种子的任务损失(双监督,更稳);C2b = 只监督精修后输出。

**主结果——精度–K 曲线**:横轴推理迭代步数 `K ∈ {0,1,2,3,5,8,15}`,纵轴末端误差(位置、姿态各一张图),三条曲线叠加。预期 C2 曲线明显**左移**(更小 `K` 即达标);左移幅度即"活搬到模型上"的程度。

- C0→C1 的左移 = 改动 A 的贡献;C1→C2 的左移 = unroll 的贡献。
- 注意:C2 的 K=0 裸输出未必比 C1 准,但其 K=2 输出应胜过 C1 的 K=2 输出——因为它学的是"两步能收尾的位置",不是"自己最近"。

## 3. 方法实现

### 3.1 可微 unroll 机制

训练时每个 unroll 步(左右臂各算,下为单臂,`q` 为 7 维),全程 torch、保持计算图:

```
# q 来自网络种子或上一步; target 为目标末端位姿
for k in range(K_train):          # K_train = 1 或 2
    T   = fk_torch(q)                          # 可微 FK
    e_p = target.t - T.t                       # 位置误差 (3)
    e_r = log3(target.R @ T.R.transpose())     # 姿态误差 (3)
    e   = cat([e_p, e_r])                       # (6)
    J   = jac_torch(q)                          # (6,7), LOCAL_WORLD_ALIGNED
    dq  = J.T @ solve(J @ J.T + (lam**2)*I6, e) # 阻尼伪逆 (7)
    dq  = clamp(dq, -0.05, 0.05)
    q   = q + dq
return q                                        # 梯度可回传到种子与网络权重
```

- 用 6×6 的 `J Jᵀ + λ²I₆` 解,等价 DLS 且比 7×7 便宜;`solve`、`clamp`、`log3` 均(几乎处处)可微。
- 全 unroll 即可(K_train 小,内存/梯度无压力);训练期监控梯度范数,异常则降 K_train 或对早期步 detach。

### 3.2 精修器对齐要求(硬门槛,见阶段 0)

训练用 torch 可微精修器(`pytorch_kinematics`),部署用生产 Pinocchio `fk_correction`。**为 torch 精修器调好的种子,必须能迁移到 Pinocchio 精修器**,否则结论不成立。二者须逐项一致(严格照报告 §2.3 / §3.2):

- 同一 `actibot_v3.urdf`,锁同样 4 个夹爪关节,保留 14 臂 DOF;
- 末端帧 `ee_left`/`ee_right`:腕前 0.15 m、横向 ±0.02 m;
- 误差定义:位置 `target.t − T.t`;姿态 `log3(R_target · Rᵀ)`;6 维;
- 雅可比:`LOCAL_WORLD_ALIGNED` 帧、6×7、取对应臂 7 列;
- 阻尼 λ=0.1,`dq` 截断 ±0.05 rad,左右臂分别迭代。

**验收**:同一批关节,torch FK vs Pinocchio FK 末端位姿差 ~µm;同种子同 K 下两精修器输出关节差可忽略。

### 3.3 数据

- **来源**:END2JOINT 演示数据 round-trip。目标 endpose = `compute_ee_pose(FK(录制 action[t,:14]))`,in-distribution、零标签噪声,与报告 L2 口径一致。
- **划分(防泄漏)**:**按 episode 切**,不按帧随机切(相邻帧高度相关会让指标虚高)。
  - train:`0525_workflow_120`(120 episodes)
  - val(调参):`0602_test_for_net`(5 episodes)
  - test(最终 round-trip + 自回归):VLA `episode_000000`(383 帧)
  - 三条件用**同一套划分**。
- **prev_joints**:训练与离线评测用 `gt` 模式(`prev = observation.state[t]`,单步、分布内);自回归漂移测试单独用 AR 模式(prev = 上一帧自身输出)。

### 3.4 训练设置(三条件严格一致,只差损失/unroll)

- 同一网络结构(`[400,300,200,100,50]`、ReLU+Dropout、标准化/反标准化流程)、同数据、同优化器与预算、同输入编码。
- 损失:C1/C2 主项为 FK 位置 + 姿态损失,仅"算在裸种子上 / 算在精修后输出上"不同。
- 可选向 `prev_joints` 的零空间投影正则(对应报告 6.2,处理 7-DOF 冗余、肘部贴近录制):**三条件要么都开同权重、要么都关**,不得成为隐藏变量。
- `K_train` 必须小(1~2):太大则精修器啥都能修、种子梯度趋零,C2 退化成 C0 换皮。监控"种子本身(K=0)误差是否在变好",作为 unroll 起作用的直接证据。

## 4. 评测协议

所有训练好的模型,**一律用生产 Pinocchio fk_correction** 扫 `K`,测"给定部署精修器,该种子需要几步"。


| 指标              | 定义                                                    | 作用                                    |
| --------------- | ----------------------------------------------------- | ------------------------------------- |
| **末端位置误差(mm)**  | `FK(q_final)` vs 目标 endpose 的 xyz 差,mean / max(或 P95) | 主精度指标                                 |
| **末端姿态误差(deg)** | 同上,旋转差                                                | 主精度指标                                 |
| **K**           | 达到部署目标(pos<1mm & ori<0.5°)的最小 `K`                     | 直接量化"少迭代"程度                           |
| **精度地板**        | `K=15` 时误差                                            | 确认天花板未被牺牲                             |
| **关节 MAE(deg)** | vs 录制 action                                          | 续报告口径;因冗余,**仅作参考、非主指标**               |
| **自回归漂移**       | AR 模式跑满 383 帧,误差随时间曲线                                 | README 显示 AR 会从 ~1° 炸到 ~5.8°,这是部署真实风险 |
| **单帧延迟(μs)**    | 各自 `K`* 下:网络前向 + K 步精修                                | 续 README 60/92/170μs 口径               |
| **自碰撞率 / 限位越界** | 用 URDF 在 PyBullet/MuJoCo 统计                           | 防止"少迭代"换来不可执行解                        |


**强约束**:任何"少迭代"结论**必须在自回归模式下复测**,不得只看单步离线 MAE。

## 5. 分阶段计划

### 阶段 0 — 排雷(1~2 天)【硬门槛】

- **目的**:做出 torch 可微精修器,并验到与 Pinocchio µm 级一致。
- **任务**:`pytorch_kinematics` 加载 `actibot_v3.urdf`、定义 `ee_left`/`ee_right` 帧、实现 §3.1 的可微 DLS 迭代、写对齐校验脚本(对比 torch FK 与 Pinocchio FK、对比两精修器输出)。
- **交付物**:`diff_refiner.py`(可微精修器)+ `check_alignment.py`(校验脚本)+ 校验报告。
- **通过标准(Gate-0)**:FK 末端位姿差 ~µm;同种子同 K 下两精修器输出关节差可忽略。**不过不进阶段 1。**

### 阶段 1 — Smoke Test(2~3 天)【方向门槛】

- **目的**:用最小代价确认 C2 曲线确实左移,验证 unroll 实现方向正确。
- **任务**:在 train 子集上跑 C0 与 C2,只画**位置精度–K 曲线**。
- **交付物**:C0 vs C2 位置精度–K 图 + 简短结论。
- **通过标准(Gate-1)**:C2 曲线相对 C0 明显左移。若方向不对,回阶段 0 排查 unroll 实现/对齐,不进阶段 2。

### 阶段 2 — 完整实验(1~2 周)

- **目的**:补齐 C1、全量训练,出完整证据与决策结论。
- **任务**:
  1. 三条件(含 C2a/C2b)全量训练,同预算;
  2. 全指标评测:位置/姿态精度–K 曲线、`K`*、精度地板、关节 MAE;
  3. 自回归漂移测试(各条件在各自 `K*` 下);
  4. 单帧延迟测量;
  5. 用 URDF 在 PyBullet/MuJoCo 统计自碰撞率与限位越界。
- **交付物**:完整实验报告——三条件精度–K 曲线、`K`* 与延迟对照表、自回归漂移曲线、碰撞统计、依 §1 决策规则得出的明确结论(采纳 unroll / 只采纳任务损失 / 维持现状)。
- **通过标准**:依 §1 预登记决策规则给出可执行结论。

## 6. 风险与对策


| 风险                              | 对策                                          |
| ------------------------------- | ------------------------------------------- |
| torch 精修器与 Pinocchio 不一致,结论不可迁移 | 阶段 0 硬门槛,µm 级对齐校验通过才往下                      |
| `K_train` 设大 → 种子梯度趋零、C2 退化成 C0 | `K_train=1~2`;监控 K=0 种子误差是否变好作为 unroll 生效证据 |
| 冗余混淆:末端完美但关节与录制不同               | 末端误差为主指标,关节 MAE 仅参考(报告已踩明)                  |
| 只看单步离线、漏掉闭环漂移                   | 所有"少迭代"结论必须在自回归模式复测                         |
| 对 `K_train` 过拟合,种子只在特定步数好用      | 推理 K 在 `K_train` 上下都扫                       |
| 全 unroll 梯度病态/爆炸                | 监控梯度范数;必要时降 K_train 或对早期步 detach            |
| C0→C1 与 C1→C2 功劳混淆              | 必设 C1 中间条件,严格控制三条件其余变量一致                    |
| 减少迭代换来不可执行解                     | 评测纳入自碰撞率/限位越界,作为否决项                         |

## 附录 A:为什么训练阶段必须可微

C2 的损失定义在**精修后输出**,要更新的是网络权重,梯度须穿过精修器:

```
∂Loss/∂θ = ∂Loss/∂q_final · ∂q_final/∂q_seed · ∂q_seed/∂θ
                              └── 精修器雅可比 ──┘
```

中间项 `∂q_final/∂q_seed` 即精修器的雅可比,起**梯度滤波**作用:精修器能强收缩的方向(它修得了)梯度被衰减,告诉网络"别费劲";精修器收缩不动的方向(分支选择、冗余消歧、吸引域之外)梯度被保留,逼网络学好。**没有可微,就没有这个雅可比,refiner-aware 训练无从谈起**,只能退回 C1(仅优化裸种子)。

可微仅训练时需要;部署是纯前向数值迭代,不需梯度。

## 附录 B:torch 精修器 vs Pinocchio 的取舍

- torch 精修器可微,因为 DLS 每步(FK、log3、矩阵乘、线性求解、clamp、加法)都是可微初等运算,`pytorch_kinematics` 把运动学放进 autograd 图。
- Pinocchio "不可微"指它不在 PyTorch autograd 图内、无法直接对网络权重回传,而非数学上无导数。
- 部署用 torch 精修器**技术可行**(纯前向、可 GPU 批量),但实时控制回路中 Python+torch runtime 比纯 C++/Pinocchio 数值迭代重;单臂 6×7 DLS 在 C++ 是几 µs 级。
- 无论部署选哪个,**真正不能省的约束是"训练用的精修器与部署用的精修器必须对齐"**(阶段 0)。
